# 数据与业务契约

enrolled 为实际报名，不是未受容量约束的需求；waitlist 缺失表示未观测，不能当零。共享课程仍是一条 course，campuses 列出参与校区。known_at 是计划可被使用的最早时点，effective/target 是业务生效期。

## 数据集合

- `courses`：主键为 `course`；必填字段 `course, title, topic, campuses, capacity, introduced`，当前 9 条。
- `history`：主键为 `course + term`；必填字段 `course, term, published_at, seats, enrolled`，当前 64 条。
- `plans`：主键为 `plan`；必填字段 `plan, known_at, target, courses`，当前 2 条。
- `relations`：主键为 `relation`；必填字段 `relation, effective, known_at, parents, child, meaning`，当前 1 条。
- `reservations`：主键为 `campus + term`；必填字段 `campus, term, teacher_hours`，当前 3 条。
- `forecasts`：主键为 `release + course`；必填字段 `release, course, target, issued_at, point, plan`，当前 8 条。

集合中的主键不得重复；schema 的 foreign 引用须指向已存在的记录。可空字段保留 null 的业务含义，不自动补零。

## 查询与材料

GET 查询使用 UTF-8 JSON，错误参数返回 400，不存在的接口返回 404。重复的单值参数视为无效。summary 与 HTTP 调用同一组只读计算，材料包含数据内容指纹和生成时间，便于核对输入。

| 接口 | 作用 |
| --- | --- |
| `/api/history` | 观测序列，保留 `capacity_hit` |
| `/api/forecast` | 课程、校区、方向、全县四层需求区间与超容量风险 |
| `/api/releases` | 历史预测按发布时口径回测 |
| `/api/methods` | 候选办法在连续招生期上的比较 |
| `/api/reservation-basis` | 可支持的风险转成校区预留依据 |

`as_of` 为时点截断，默认 `2026-11-01`。`target` 默认取该时点已知的最新计划所指向的学期。`method` 可显式指定，缺省时按回测选择。

## 需求预测口径

- **只用当时已知材料**：历史记录要求 `published_at <= as_of`；计划要求 `known_at <= as_of`；课程关系统一要求 `known_at <= as_of` 且 `effective <= target`。目标学期之后才发布的计划和课程归属不参与预测，避免用后见之明回填。
- **满班是右删失**：`enrolled >= seats` 时只证明需求至少达到座位数，不证明需求恰等于座位数。删失观测在拟合中作为下界处理；有 `waitlist` 时下界提高到 `enrolled + waitlist`，`waitlist` 为 null 表示未知，不当作 0。
- **四层区间各自取分位**：每层先把课程需求分布聚合成该层的分布，再读取 10%/90% 分位，输出为 `low`/`high`。人数期望（`expected`/`point`）可加：课程合计 = 校区合计 = 方向合计 = 全县；**区间端点不可相加**，跨层相加会把不同分位混为一个人数。响应中的 `consistency` 会核对可加关系，并明确 `endpoints_additive=false`。
- **共享课程只算一次**：合办课程在课程层和全县层各出现一次；在校区层按分校份额划分，各校区人数之和等于该课程的全县人数，不会在两个校区各算一遍。`split_distribution` 对每个可能人数做整数分配，保证分校区之和还原原值。
- **超容量风险**：`over_capacity_risk` 是聚合分布中需求超过容量（或容量份额）的概率，与 `headroom = capacity - expected` 同源，均为 0–1 概率与人数差值，不是百分比。
- **新课借用证据**：新课没有自身历史时，先看 `relations` 中 `child` 指向它的关系，按 `parents` 借用历史；无关系时按同标题、再按同方向借用，并逐个列出借用的课程、关系、时点与观测。`evidence.uses_observations_after_cutoff` 恒为 false，新课从不用其后来实际招到的人证明当初预测。

## 候选办法与回测

候选办法：

- `censored_tobit`：删失正态模型，用 EM 拟合，满班作为下界；
- `censored_empirical`：对历史观测做加权经验分布，满班值取「座位数 + 未满班时的典型余量」，近期学期权重更高；
- `last_observed`：旧口径，直接取最近一次观测。

回测在连续招生期上进行：预测第 N 期只用第 N 期发布前的历史，逐课程逐期与第 N 期实际观测比较。满班期的实际值只按座位数作为下界计分，因此区间覆盖不等于「命中座位数」。`selection_score = 10×|覆盖率−80%| + 2×平均缺口 + 0.02×平均区间宽度`，兼顾区间可信度与师资不足代价；删失办法在不明显更差时优先，避免把满班人数当成真实需求。

## 历史预测回测

`/api/releases` 用发布时已知的计划解释每条历史预测：发布记录若指向当时已存在的计划，用该计划快照；`legacy` 等未指向持久计划的发布，用该发布自己的课程集合作为快照。后来新增的计划、关系或课程不会改变旧发布的解释口径。已发布记录的 `point` 原样保留，不回写。

## 现有办理协作

- `staffing.propose`：记录课程组合与所需时段，并附上该校区的需求依据（`demand_basis`：区间、风险、建议席位与工时）。跨校合办课程按校区分别列出，教师确认的时段是整段时间。
- `teacher_contracts.confirm`：教师按整段时间确认。只确认部分时段时，可保障容量按确认段数占请求段数的比例折算（`capacity_basis = confirmed_share_of_teacher_capacity`），`unconfirmed_slots` 列出未确认时段；同一教师同一时段不得在两个校区或两个预留中被同时许诺。
- `admissions.publish`：发布有席位保证的名额，席位不得超过已确认容量，也不得超过预测支持的需求上界与校区容量。已确认的课程组合不能被改单，调整课程组合时既有的确认工时不会悄悄挪给新课。

每个操作在本地业务日志的事务中更新；失败不提交半条办理记录。接口传入业务标识，未知标识或不满足条件返回错误，不自动补建对象。
